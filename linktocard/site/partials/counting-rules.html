One image is one rendered size counts 1
The same card rendered in two sizes is two images.
Failed renders never count counts 0
If a render ends in an error, nothing is taken from your quota.
Cache hits never count counts 0
A rendered image is kept for [[plan.free.cacheDays]] days on [[plan.free.name]], [[plan.starter.cacheDays]] on [[plan.starter.name]] and [[plan.pro.cacheDays]] on [[plan.pro.name]]. Requests for it in that time are served from cache and are not counted again.
Unused quota does not roll over
The monthly allowance resets at the start of each billing period.
The limit is a hard stop
When the allowance and any top-up images are used up, new renders answer HTTP 402 until the next period. There is no overage billing on any plan.
Top-ups are manual
On [[topup.plans]], you can buy [[topup.images]] extra images for [[topup.price]] whenever you choose. A top-up is never bought or billed automatically. [[topup.keepsPlanShort]] [[> topup-closed-note]]
A PDF counts by its pages counts [[pdf.baseUnits]]–[[pdf.maxUnits]]
A PDF of 1 to [[pdf.basePages]] pages counts as [[pdf.baseUnits]] images, and each further [[pdf.extraPagesPerUnit]] pages started add one more, up to [[pdf.maxUnits]] images for the longest PDF of [[pdf.maxPages]] pages. It is taken as one block, from the monthly allowance or from one top-up, never split between them. Failed renders and stored PDFs served again count nothing, as for images. How PDFs are counted
Bulk documents count document by document per document
A batch makes one PDF per row, and each is counted like a PDF of its own pages when it is made. A batch starts only when at least [[pdf.baseUnits]] images per row are left. Documents that fail or are cancelled before they start count nothing. How batches are counted
The PDF toolkit counts by the pages it delivers counts 1 per [[toolkit.pagesPerUnit]] pages
A merge, split, stamp, fill, image-to-PDF or protect request counts one image for each started block of [[toolkit.pagesPerUnit]] pages of its result, at least one, taken as one block; a split counts each new file on its own pages. Reading a form's fields counts nothing. Every request that succeeds counts, also the same request again. How the toolkit is counted
A card from a link is a card counts 1
A card made from a page's own title and description counts one image, and the same card again counts nothing while it is stored. Reading the page never counts as an image. Details
Email images count once per distinct value counts 1
Each distinct reader value, such as a first name, is one card: rendered and counted once, then served from storage to everyone with that value. When its stored copy expires, it is rendered again without being counted again, for [[email.chargeMemoryDays]] days from its count. Details
A chart image counts once counts 1
A new chart counts one image the first time it is drawn, and repeat views count nothing. When its stored copy expires, it is drawn again without being counted again, for [[charts.chargeMemoryDays]] days from its count. The free chart maker counts nothing. Details
