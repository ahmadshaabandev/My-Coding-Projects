    About the checker

    What it does, and what it does not.

    What it does

    • Fetches the one page you paste, from our server, as LinkToCardBot/1.0. It follows up to 3 redirects and checks every address on the way.
    • Reads og:* and twitter:* tags, the <title>, the meta description, the canonical link, the favicon and theme-color.
    • Downloads the og:image (or twitter:image) to measure its HTTP status, type, file size, pixel size and aspect ratio.
    • Reads the site's robots.txt and tells you if it disallows the checker or all bots for that page.
    • Runs twelve checks, each with a plain fix, and draws approximate previews from what it found.

    What it does not do

    • It does not run JavaScript. Tags that your page adds in the browser after it loads are not seen, so put them in the HTML your server sends.
    • It does not crawl. Per check it requests the page, its robots.txt and its image (a HEAD, then a GET), and nothing else. The image and favicon are fetched again only to show them to you here.
    • It does not log in, and it cannot reach localhost, private networks or plain http:// pages.
    • It cannot see what an app has already cached for your link, and it does not ask any app to refresh it.
    • It never stores or returns the page's HTML: only the parsed tags and the results, for 10 minutes.

    Why the previews differ between apps

    Every app that unfurls a link runs its own fetcher and draws its own card. They read the same tags, but each decides how large the image is, how it is cropped, how many lines of title and description fit, whether the site name or favicon appears, and how long the result is cached. Some use a different tag first: X looks for twitter:* tags, most others for og:*.

    The mockups on this page use the same parsed data in six approximate layouts. They are close enough to spot a missing image, a bad crop or a title that is cut off; they are not a promise of the exact pixels.

    FAQ

    Questions about link previews.

    Short answers, and where we are not sure, we say so.

    I fixed my tags. Why does the old preview still show?

    Apps cache what they fetched for a URL, and most do not say for how long. This checker always reads your page fresh (after its own 10-minute cache), but it cannot clear another app's cache.

    Facebook's Sharing Debugger and LinkedIn's Post Inspector let you ask those two to fetch the page again. For other apps, sharing the URL with a small change, such as ?v=2 on the end, makes it a new URL that they have not cached yet.

    What size should my og:image be?

    1200 × 630 pixels is the size most sites use. It is the 1.91:1 shape this checker tests for, and it is large enough to look sharp in the big-image layouts. Keep the file well under 5 MB, use PNG or JPEG, and give it an absolute https:// URL.

    Keep text and faces away from the edges: some apps crop the image to a square or a smaller rectangle.

    Do I need twitter: tags if I already have og: tags?

    Set twitter:card at least. It has no Open Graph equivalent: it names the layout you want, and summary_large_image asks for the big image. For title, description and image, X can read the og: versions when the twitter: ones are missing; add twitter: tags only when you want different text on X.

    The checker says robots.txt blocks it. Does that matter?

    The checker fetches a page only because a person asked for it, like a link preview does, so it reports robots.txt as a warning and still reads the page. Some link-preview fetchers may follow robots.txt more strictly, so a rule that blocks all bots from a page you want shared is worth a second look.

    Why can I not check my localhost or staging site?

    The checker only fetches public https:// addresses, and it refuses anything that resolves to a private, local or reserved network, so it cannot be used to probe networks it should not see. A page behind a login is fetched as a logged-out visitor, which is what the apps see too.

    Is it free? Are there limits?

    Yes, and you do not need an account. There is an hourly limit on fresh checks from one network, and after a few checks you may be asked to confirm you are a person. A URL checked in the last 10 minutes is answered from the cache and does not count.

    For regular use, the inspect API gives each API key its own daily allowance.

    What does the checker keep?

    The parsed tags and the check results, for 10 minutes, so the result and its image can be shown and shared. It never keeps the page's HTML. To show the image, it is fetched again from your server through our own address; nothing is stored. Privacy policy
