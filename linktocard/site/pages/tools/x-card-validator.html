      About the validator

      What it checks, and what it cannot know.

      What it checks

      • The twitter:card, twitter:title, twitter:description, twitter:image and twitter:site tags, next to the og: tags and the page's <title>.
      • The image the tags point to: whether it loads, its type, file size, pixel size and shape.
      • That the card images are on https:// addresses: X's developer policy says all assets within a card must be hosted on HTTPS.
      • Everything the Open Graph checker checks, with the same plain fix for each problem.

      What it cannot know

      • When we checked in November 2026, X's developer documentation at docs.x.com had no page about card markup. So this page gives no X image sizes, limits or cache times, and calls its mockup approximate.
      • twitter:card is the tag that names the card type. The values in common use are summary, a small image beside the text, and summary_large_image, a large image above it. That is our understanding, not a rule we could read in X's current documentation.
      • It cannot see what X has already cached for your link, and it does not ask X to fetch the page again.

      More on this in the guide Twitter card not showing on X.

      FAQ

      Questions about X cards.

      Short answers, and where we are not sure, we say so.

      Is this X's own Card Validator?

      No. It is an independent checker made by [[site.name]]. It reads the same tags a card is built from and draws an approximate card; it cannot show you X's own rendering.

      X's current developer documentation does not describe a card validator, so we do not say whether X still offers one.

      Do I need twitter: tags if I already have og: tags?

      Set twitter:card at least: it has no Open Graph equivalent, and summary_large_image is the value in common use for a large image. Our understanding is that X falls back to the og: tags for the title, description and image when the twitter: ones are missing, but we could not confirm it in X's current documentation. If the card shows the wrong text, setting the twitter: versions explicitly is the quick test.

      I fixed my tags. Why does X still show the old card?

      Apps cache what they fetched for a link, and we could not find X's cache time in its current documentation. A URL with a small change, such as ?v=2 on the end, is usually treated as a new link and fetched fresh.

      What image should a large card use?

      We cannot quote X's own numbers, so here is the safe choice: a [[size.og.width]] × [[size.og.height]] PNG or JPEG on an https:// address, well under [[inspect.imageWarnMb]] MB, with text and faces kept away from the edges in case X crops it.

      Is it free? What does the checker keep?

      Yes, and you do not need an account. There is an hourly limit on fresh checks from one network, and after a few checks you may be asked to confirm you are a person. The checker keeps the parsed tags and the check results for [[inspect.cacheMinutes]] minutes, never the page's HTML. Privacy policy
