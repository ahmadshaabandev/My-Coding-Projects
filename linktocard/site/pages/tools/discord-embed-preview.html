      TagValue

      How Discord reads a link

      What the embed is made of.

      Discord documents how it builds a link preview. These are the rules this page checks, in short.

      The fetch

      • Discord makes a single GET request for the shared URL and runs no code, so tags that a script adds after the page loads are never seen.
      • The answer must be a 2xx HTML page (text/html or application/xhtml+xml), reached in at most 5 redirects and at most 50 MB.
      • The whole fetch, measuring the images included, must finish within 10 seconds. Without og:image:width and og:image:height, Discord downloads the image to measure it.

      The text

      • The title comes from og:title or twitter:title, the description from og:description or twitter:description, and og:site_name is shown above the title.
      • <title> and the meta description are used only as a pair, and only when the page has no Open Graph or Twitter title or description.
      • A title over 70 bytes or 3 lines and a description over 350 bytes or 20 lines are trimmed. The description is plain text: HTML tags in it appear literally.
      • An og:site_name over 256 characters, image alt text over 4,096 characters or any URL over 2,048 characters means no preview at all.

      The layout and the colour

      • The tags decide the layout, not the size of the image. With no layout tag, the text comes with a small image beside it.
      • twitter:card set to summary_large_image puts a large image below the text; photo shows the image on its own; og:type set to rich gives Discord markdown text with a small thumbnail.
      • Two or more og:image tags make a gallery of up to 4 images.
      • theme-color sets the accent colour, written as #RRGGBB or #RRGGBBAA only.
      • Images can be PNG, GIF, JPEG, WebP or AVIF. A relative image URL must start with /.

      What this page cannot check

      • The checker reads the first og:image only, so it cannot tell whether Discord will show a gallery. It does not read image alt text, oEmbed, publish dates or video tags either.
      • When a tag is repeated, the checker keeps the first value. Discord does the same for the title, description and site name, but uses the last one for layout and colour tags, and its tag names are case-sensitive, while the checker also reads OG:Title.
      • The checker fetches https:// pages only and follows up to [[inspect.maxRedirects]] redirects. Discord also reads http:// pages and follows up to 5.

      FAQ

      Questions about Discord embeds.

      Short answers, and where we are not sure, we say so.

      Why is my image small in Discord?

      Discord picks the layout from your tags, not from the image. Without a layout tag it shows the text with a small image. Add <meta name="twitter:card" content="summary_large_image"> to get the large image below the text.

      I fixed my tags. Why does Discord still show the old embed?

      Discord caches previews for about 30 minutes. To see the change at once, share the URL with a new query string, such as ?v=2 on the end.

      Discord's own Embed Debugger shows which tags Discord picked up for a URL and which layout it chose.

      Why does Discord ignore my theme-color?

      Discord takes the accent colour only as a 6- or 8-digit hex value, such as #2f6feb. A short form such as #fff, a colour name or rgb() is not used. If the page repeats theme-color, Discord uses the last one.

      Is this Discord's own tool?

      No. It is an independent checker made by [[site.name]], not by Discord, and the embed it draws is a mockup. For what Discord itself sees, use Discord's Embed Debugger.

      Is it free? What does the checker keep?

      Yes, and you do not need an account. There is an hourly limit on fresh checks from one network, and after a few checks you may be asked to confirm you are a person.
