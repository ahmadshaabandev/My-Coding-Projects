YOUR_SITE_ID and YOUR_SIGNATURE are placeholders. A free account gives you a site id and a signing secret; the signature is an HMAC of the URL made with that secret, so the playground cannot hand out working signed URLs.

How it works

Three steps, no browser to run.

Cards are rendered from HTML and CSS directly. There is no headless browser to host, patch or wait for.

  1. Pick or write a template

    Start from a starter template or write your own in HTML and CSS, with {{placeholders}} for the parts that change from page to page.

  2. Sign the URL

    Create a site to get its id and secret. Your server or build script signs each image URL with HMAC-SHA256, a few lines in any language.

  3. Paste it into your meta tags

    The first request renders the image and stores it. Later requests for the same URL are served from cache and do not count again while it is stored.

Prefer to render ahead of time? POST /v1/images with an API key returns the image URL. The docs cover both.

FAQ

Honest answers.

Including the things this product does not do.

What is [[site.name]], and what is it not?

It renders Open Graph and social card images from HTML and CSS templates, either through a signed URL you put in your meta tags or through an API call.

It is not a visual editor: templates are code. It does not take screenshots of web pages, it does not make video or GIFs, and it does not generate images with AI.

How do signed URLs stop other people from using my quota?

Every image URL carries a signature, an HMAC-SHA256 of its path and parameters made with your site's secret. Someone who changes the text in the URL, or invents a new one, cannot produce a valid signature without that secret. The request is rejected with HTTP 403 before anything is rendered, so it never counts.

What happens when I reach my limit?

New renders stop and the API answers HTTP 402 until your next billing period. Images that are already rendered and still cached keep being served.

On [[plan.free.name]] that is a hard stop. On [[plan.starter.name]] and [[plan.pro.name]] you can buy a top-up of [[topup.images]] images for [[topup.price]], or change plan. Nothing is ever charged automatically beyond your subscription.

How does the cache work, and when is an image counted again?

A rendered image is stored for [[plan.free.cacheDays]] days on [[plan.free.name]], [[plan.starter.cacheDays]] days on [[plan.starter.name]] and [[plan.pro.cacheDays]] days on [[plan.pro.name]]. While it is stored, requests for the same URL are served from cache and are not counted.

After that, the next request renders the image again and counts as one image. A different URL, for example a new title or another size, is a different image.

Which fonts, emoji and languages work?

The bundled fonts cover Latin, Cyrillic, Greek and Vietnamese. Other scripts need a font that you upload, which requires a paid plan. Emoji are drawn with the open-source Twemoji graphics.

Right-to-left and complex scripts, such as Arabic or Hebrew, have limited support in the rendering engine. Test your own text before you rely on it.
